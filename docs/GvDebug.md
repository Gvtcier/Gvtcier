# GvDebug 仿真调试

GvDebug 是 GvtcierXuNiJi（最小虚拟机）的调试模块。仿真器验证内核的磁盘与网络行为时，GvDebug 记录操作过程并在失败时给出定位信息。

## 背景

仿真器验证时的调试难点：

- 命令解析失败时难以确定卡在哪一步
- 串口日志可能丢失，无法回看完整过程
- 外部调试器接入复杂

GvDebug 在仿真器内部记录并汇总验证过程，输出可直接使用的报告。

## 架构

GvDebug 由四个部分组成：

- 监控点：按地址范围与读写类型设置，命中时计数
- 操作轨迹：按步骤记录解析与执行过程，超过上限时丢弃最早记录
- 现场转储：按地址范围输出内存十六进制片段
- 调试报告：汇总监控命中与完整轨迹

模块源码位于 GvtcierXuNiJi\src\gvdebug.rs。

## 集成

AHCI 仿真：

- 写入 CLB/FIS/PRDT 区域时检查监控点
- 命令解析的每个步骤写入轨迹
- 执行失败时输出报告与现场转储

网络仿真：记录初始化序列与帧验证过程。

## 使用

运行 GvtcierXuNiJi 即自动启用。验证成功时报告包含命中统计与轨迹；失败时报告附现场转储。

报告示例：

```
== GvDebug 报告 ==
监控 CLB/FIS/PRDT 区域 命中 9 次
轨迹 6 条
  [0001] 仿真启动: 装载 CLB/FIS/PRDT
  [0002] CLB: cfl=5 prdtl=1 tbl=0x78080
  [0003] FIS 校验通过: cmd=0x25 lba=0 count=1
  [0004] PRD[0]: addr=0x2b9638 size=512
  [0005] DMA 完成: lba=0 count=1 目标 1 项
  [0006] 命令解析与执行成功
```

## 报告解读

- 监控命中：确认相关区域被实际写入
- 轨迹条目：每个步骤对应一次解析或执行动作
- 失败定位：轨迹停留在失败前的最后一步，现场转储给出该区域内容

## 扩展

可增加：

- IO 寄存器监控
- 值条件断点
- 轨迹导出到文件
- 与 Gvt 结合保存多轮验证轨迹
