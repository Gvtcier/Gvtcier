# 裂变模型

本文档描述 Gvtcier 的进程创建机制——裂变。

## 概述

裂变是 Gvtcier 的进程创建机制。父进程通过系统调用直接分裂出子进程，子进程从出生起即持有定义好的权能（capability）集合。

裂变与传统的 fork 模型不同：fork 复制父进程的完整地址空间，裂变则创建一个新的进程映像，并为其分配独立的地址空间与权能。

## 权能与权限

权能是 Gvtcier 的权限单元。每个进程在创建时被赋予一组权能，描述其对端点的访问权限：

- 发送权（send）：允许向端点发送消息
- 接收权（recv）：允许从端点接收消息

权能定义在进程创建时确定，运行期间不可变更。

## 系统调用

裂变通过系统调用 38 发起：

- 参数：进程映像指针、映像长度、权能定义指针、权能数量
- 返回值：子进程标识（id）

内核在分裂过程中：

1. 分配独立页表（PML4）
2. 加载进程映像
3. 映射用户栈
4. 按权能定义设置子进程权能
5. 记录父子关系

### 裂变与 fork 的差异(技术线)

| 维度 | fork | 裂变(fission) |
|------|------|----------------|
| 地址空间 | 完整复制父进程 | 新建独立映像,不复制 |
| 权能 | 继承全部 | 创建时显式定义集合 |
| 代价 | 复制全部页表与内存 | 仅加载新映像 |
| 用途 | 派生同逻辑进程 | 启动新程序,最小化拷贝 |

### 数据流

```
父进程 ──syscall 38(映像 + 权能定义)──▶ 内核
  → 分配 PML4/页表页
  → load_elf 解析并加载映像段(含 BSS 清零)
  → 映射用户栈(写时复制零页)
  → 按权能表设置子进程 caps
  → 返回子进程 id,子进程进入 Ready 队列
```

- 用户栈采用写时复制(CoW):所有任务共享零页,首次写入触发内核复制,降低内存占用
- 权能集合在创建时定死,运行期不可变更——资源访问范围由出生时的定义决定

## 进程关系

每个进程持有父进程标识（parent）。父子关系在裂变时建立，用于标识进程来源。

## 使用

进程调用裂变系统调用，传入映像与权能定义，内核创建子进程并返回其标识。
