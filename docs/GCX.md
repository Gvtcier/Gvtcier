# GCX 内核格式

GCX（GvtcierChengXu）是 Gvtcier 内核使用的可执行格式，文件扩展名为 .gcx，魔数为 0x786367（"gcx"）。

## 设计动机

GCX 是内核可执行格式,为什么不用 ELF 直接引导?

- **ELF 面向通用加载器**:程序头(PT_LOAD)描述的是"文件→虚拟地址"映射,但 Gvtcier 自研引导层需要精确控制物理加载地址,且不依赖 ELF 解析器
- **gcx 简化引导**:段表显式给出"文件偏移 + 虚拟地址 + 大小",引导程序按表复制即可,无需解析复杂结构
- **虚拟基址使重定位零成本**:段内代码以 `KERNEL_VIRT` 为基址链接,加载时物理地址 = 虚拟地址 − 基址,页表再按 KERNEL_VIRT 恒等映射,代码无需重定位

## 文件布局

| 区域 | 大小 | 说明 |
|------|------|------|
| 头部 | 64 字节 | 魔数、版本、段数、入口、虚拟基址、段表偏移 |
| 段表 | 40 字节 × 段数 | 每段：文件偏移、虚拟地址、文件大小、内存大小、标志 |
| 段数据 | 变长 | 各段内容，在 gcx 内连续排列 |

## 头部字段（64 字节）

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 8 | 魔数 | 0x786367（"gcx"） |
| 8 | 4 | 版本 | 当前为 1 |
| 12 | 4 | 段数 | 段表项数量 |
| 16 | 8 | 入口 | 内核入口虚拟地址 |
| 24 | 8 | 虚拟基址 | 内核虚拟基址，物理地址 = 虚拟地址 - 基址 |
| 32 | 8 | 段表偏移 | 段表在文件中的偏移（当前为 64） |
| 40 | 24 | 保留 | 全零 |

## 段表项（40 字节）

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 8 | 文件偏移 | 段数据在文件中的偏移 |
| 8 | 8 | 虚拟地址 | 段加载到的虚拟地址 |
| 16 | 8 | 文件大小 | 段在文件中的字节数 |
| 24 | 8 | 内存大小 | 段在内存中的字节数，超出文件大小的部分清零 |
| 32 | 8 | 标志 | 当前为 0 |

## 工具

gvtcier-gcx 将内核 ELF 打包为 gcx：

```
gvtcier-gcx <kernel.elf> <out.gcx>
```

输出包含 ELF 中全部 PT_LOAD 段，段数据在 gcx 内连续排列，文件偏移重新计算。

## 加载

引导程序读取 \KERNEL.GCX,校验魔数后按段表将各段复制到（虚拟地址 - 虚拟基址）对应的物理地址,超出文件大小的部分清零,然后跳转入口地址。

### 加载流程技术线

```
引导层读 KERNEL.GCX
  → 校验魔数 0x786367
  → 读头部(段数/入口/虚拟基址)
  → 逐段:物理地址 = 段虚拟地址 − 虚拟基址
  → 复制段数据,内存大小超出文件大小的部分清零(BSS 归零)
  → 跳转入口地址,进入内核
```

- **物理地址换算**:内核链接于 `KERNEL_VIRT`,段虚拟地址减去基址即得物理地址,引导层据此写入真实内存
- **BSS 归零**:`内存大小 > 文件大小` 的段,未覆盖区域显式清零,保证未初始化全局变量为 0
- **段顺序**:段数据在 gcx 内连续排列,文件偏移由打包工具重新计算,引导层按序读取

gcx 文件由 ISO 打包工具放入启动镜像,文件名为 KERNEL.GCX。
